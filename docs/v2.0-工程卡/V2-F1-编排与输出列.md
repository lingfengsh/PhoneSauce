## 0. 目标一句话

`engine.py`：单个 wav → 按勾选项调度 F0/Formant 引擎 + 测量算法 → 产出 67 列参数字典（VoiceSauce 原生列名）。这是 pysauce 的唯一对外入口（F2 的 server 只调它）。

## 0b. 【硬性】与向导界面的数据互通（不得破坏）

**背景事实（已核实）**：1.2 的向导页与 vs 页**共用音频目录下的 `measure/` 目录**——
- 向导页跑 Praat 脚本产出 `measure/<base>.Pitch`、`measure/<base>.Formant`、`measure/<base>.measure.json`；
- vs 页显示/导出时**自动读同一批 `measure/` 文件**（`vs.js` L338/L639「数据自动从 …/measure 读取」、L664 注释「两界面数据互通」）；
- 后端已有复用开关 `pitchRead`/`pitchReadDir`/`formantRead`/`formantReadDir`（`params_schema.py` L260–273）与 `reuse` 参数（`server.py` L1126）。

**因此 pysauce 必须遵守**（违反即废工）：

1. **F0/Formant 来源优先级**：若用户已勾选「复用已有 Pitch/Formant」（`reuse=true` 且 `measure/` 下有对应文件）→ **必须直接读取该文件**，不得重算。这既省算力，也保证「向导用 Praat 做好的 F0/Formant，到 vs 页可直接用于算其他参数」。
2. **产出落盘位置**：pysauce 自己算出的 F0/Formant **必须写回同一 `measure/` 目录**，文件名与格式与 1.2 完全一致（`.Pitch`/`.Formant`），使向导页能反向读取。
3. **格式兼容（分引擎，2026-10-26 修正）**：
   - **Praat 引擎**：读写走 `praat_objects.read_pitch_text/write_pitch_text/read_formant_text/write_formant_text`（1.2 现役模块，A1 卡已复制到 v2），落 `measure/<base>.Pitch` / `.Formant`，**格式与 1.2 完全一致**（向导页反向可读）。
   - **非 Praat 引擎（Snack / STRAIGHT）**：**绝不写成 Praat 对象格式**——那是伪造 Praat 对象，语义错、字段对不上。改用**自有简单格式**（纯文本：`# engine=snack dim=f0` 头 + 每行 `time<TAB>value`，或等价 JSON），落**带引擎后缀**的文件：`measure/<base>.sF0` / `.sFormant`（Snack）、`measure/<base>.strF0`（STRAIGHT）。后缀口径见 `review_export.ENGINE_OBJECT_EXT`。
   - **禁止**把不同引擎的结果写进同一个 `.Pitch`（会互相覆盖、且无从判断来源）。
4. **EngineRequest 新增字段**（见 §2）：`reuse: bool`、`measure_dir: str`、`pitch_read_dir: str | None`、`formant_read_dir: str | None`。
5. **测试**：§5 必须含一条互通测试（`test_measure_reuse_roundtrip`）——先写一个 `.Pitch` 到临时 measure/，再以 `reuse=True` 跑 engine，断言 F0 列来自该文件（值一致）。另需一条 `test_engine_object_suffix`：断言 `.sF0`/`.strF0`/`.sFormant` 各落各文件、互不覆盖。

## 0c. 【硬性】基准引擎选择：算多套，但下游只认一套

**VS 原始设计（已核实 `func_parseF0.m` / `func_parseFMT.m` / `vs_ParameterEstimation.m` L1019/1059/1120）**：

- 引擎计算（`pitch_engine`/`formant_engine`）决定**算哪几套**（可多套并存，各落各列 `pF0/sF0/strF0`、`pF1/sF1/oF1`）；
- **下游算法（H1/A1/2K/CPP/HNR/SoE）不直接吃某个引擎列，而是统一吃 `F0 = func_parseF0(matdata, F0algorithm)` 与 `F1,F2,F3 = func_parseFMT(matdata, FMTalgorithm)`**；
- `F0algorithm` / `FMTalgorithm` 是**用户设置项**（默认 `'F0 (Straight)'` / `'Formants (Snack)'`，见 `vs_Initialize.m` L71/72），即"**用哪套引擎结果作为下游计算基准**"；
- 结果中**记录** `AFMTalgorithm`、`H2KFMTalgorithm`（L1067/1088）——即"这一列是用哪套 FMT 算的"。

**因此 pysauce 必须实现**（违反即废工）：

1. `EngineRequest` 增加 **`f0_algorithm: str`** 与 **`fmt_algorithm: str`**（取值 = 列名前缀语义：`"praat"|"snack"|"straight"|"shr"|"other"`），与 `pitch_engine`/`formant_engine` **分开**——前者=算哪些，后者=下游用哪个。
2. 实现 `parse_f0(matdata, f0_algorithm)` 与 `parse_fmt(matdata, fmt_algorithm)`，语义严格照 `func_parseF0.m`/`func_parseFMT.m`：**指定的引擎列不存在 → 返回空**（VS 行为：`F0 = []`，下游随之产出 NaN），**不得自动回退到别的引擎**。
3. 下游每项测量调用前先 `F0 = parse_f0(...)`；A1A2A3/2K5K/斜率再 `F1,F2,F3[,B1,B2,B3] = parse_fmt(...)`。
4. **来源可追溯**：结果里附 `_meta`（`{"f0_algorithm":..., "fmt_algorithm":...}`），供 F2/F3 在表头或界面标注。
5. **跨界面互通**（§0b 的延伸）：`f0_algorithm`/`fmt_algorithm` 若指向的引擎列**来自 measure/ 复用文件**（如向导页用 Praat 做的 `.Pitch`），同样生效——即"向导页用 Praat 做 F0，vs 页设 `f0_algorithm="praat"` 即可直接用"。

## 4. engine.py 调度规格（对照蓝本行号，顺序禁改）

单文件流程（`run_file`）：

1. **读信号**：`framing.read_wav(wav_path)` → y, fs。若 `fs != 16000` 且勾选了任何 3 周期窗算法（h1h2h4/a1a2a3/2k5k）→ 按蓝本 vs_ParameterEstimation 的重采样语义处理（读蓝本 L700–760 确认：VS 是否统一重采样 16k？以蓝本为准并在对照表写明；若蓝本不重采样，则原样跑）。
2. **F0 引擎**（按 pitch_engine）：
   - **先查复用**（§0b）：`reuse=True` 且 `measure_dir/<base>.Pitch` 存在 → `praat_objects.read_pitch_text` 读取，**跳过引擎计算**，落 pF0（并记 warnings 说明来源）；
   - 否则按 pitch_engine 计算：praat → `engines.praat_f0.praat_pitch`；snack → `snack_pitch`；straight → `straight_pitch`；other → `other_pitch`。得 F0 向量映射到 1ms 网格（蓝本调度段的映射方式为准）。**写入对应列**（pF0/sF0/strF0/oF0）；
   - **算完必须落盘** `measure_dir/<base>.Pitch`（格式走 praat_objects.write_pitch_text）。
3. **Formant 引擎**：同上（复用优先 → `read_formant_text`；否则计算）→ pF1–pF4 / sF1–sF4 / oF1–oF4（+ B 列）。算完落盘 `measure_dir/<base>.Formant`。
4. **SHR**（蓝本 L764 在最前——保持此序）：`shrp.get_shrp` → SHR、shrF0 两列。
5. **测量算法**（每项仅当开关 True）：
   - **调用前先取基准**（§0c）：`F0 = parse_f0(matdata, f0_algorithm)`；需要 FMT 的项再 `F1,F2,F3[,B1,B2,B3] = parse_fmt(matdata, fmt_algorithm)`。**指定的引擎列缺失 → 空 → 该项全 NaN**（VS 行为，不自动回退）。
   - h1h2h4 → H1u/H2u/H4u
   - a1a2a3 → A1u/A2u/A3u（需 F1–F3；对应引擎列缺 NaN 则保持 NaN）
   - 2k5k → H2Ku/F2K（内部）/H5Ku
   - slopes（依赖上面三组）→ H1H2u/H2H4u/H1A1u/H1A2u/H1A3u/H42Ku/H2KH5Ku（未校正差值）+ H1c…H2KH5Kc（Iseli 校正版，B3/B4 的 c 后缀函数；带宽用 B1–B3 列，缺则 hm 公式现算——B4 已内置该逻辑）
   - energy → Energy
   - cpp → CPP
   - hnr → HNR05/15/25/35
   - soe → epoch/soe（method 由 do_soe_method）
6. **拼装**：`empty_result()` 起底，逐列填入；长度统一 1ms 帧数（对不齐的列按蓝本映射方式对齐；无法对齐 → 全列 None 并在 warnings 里记录）。结果附 `_meta = {"f0_algorithm":..., "fmt_algorithm":...}`（§0c 第 4 条）。
7. **永不 raise**：单算法失败 → 该组列 None + warnings 字符串（F2 会聚合显示）。**定案**：`run_file` 返回 `dict`，warnings 放 `result["_warnings"]`（特殊键，F2 摘出，不计入列）。

def test_measure_reuse_roundtrip(tmp_path):
    """互通：measure/ 已有 .Pitch → reuse=True 时直接复用，且值来自该文件。"""
    import os
    from backend.pysauce import praat_objects
    mdir = str(tmp_path / "measure")
    os.makedirs(mdir, exist_ok=True)
    base = "harm5"
    # 造一个已知 .Pitch（时间/频率），仅两列

    vals = [x for x in (res.get("pF0") or []) if x is not None]
    assert vals, "reuse 后 pF0 应有值"
    assert abs(vals[0] - 123.0) < 1e-6      # 值来自写入的 .Pitch，未走引擎
