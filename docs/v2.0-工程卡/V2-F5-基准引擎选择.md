## 0. 目标一句话

向导界面**第三步「批量运行」**页新增一张卡「其他参数的基准引擎」：让用户**分别**指定 F0、共振峰各用哪套引擎的结果作为下游参数（谐波/CPP/HNR/SoE…）的基准；选项按 `measure/` 里**实际存在**的对象动态启用/置灰；三套都没有则**硬拦**批量并提示先算基础数据。

## 0b. 需求原文（用户 2026-10-26）

> 向导界面，在计算所有参数页面，加一个单选框，默认都是用 praat 计算的 f0 和共振峰，同时可以选 vs 那边用其他算法算出来的 f0 和共振峰（f0 和共振峰两个单选框应该分开，不一定要用同一算法算的结果）。这一步同时可以先检查有没有比如 sF0/strF0，有则出选择项，没有则选择项变灰。如果三个算法的结果都没有，则强制在该页面算出两种数据后才能计算其他所有依赖性参数。vs 界面则按照 vs 的方式。
>
> 补充（同日）：**不改 1.2，这些改动都放在 2.0 里**；非 Praat 引擎的结果**不能做成 Praat 格式**，读写时要注意。

## 2. 数据契约

### 2b. 引擎对象后缀（`review_export.ENGINE_OBJECT_EXT`）

| 维度 | praat | snack | straight |
|---|---|---|---|
| f0 | `.Pitch`（Praat 文本格式） | `.sF0`（自有格式） | `.strF0`（自有格式） |
| formant | `.Formant`（Praat 文本格式） | `.sFormant`（自有格式） | — |

- `engine_object_path(wav, dim, engine)` → 对应文件路径；未知组合返回 `None`。
- **Praat 路径必须与 1.2 完全一致**（`engine_object_path(w,"f0","praat") == pitch_path(w)`，测试断言）。

### 2c. 探测 API `/api/engine-availability`

请求 `{dir, ext}`，返回：
```json
{"ok": true, "dir": "...", "total": 30,
 "f0": {"praat": 30, "snack": 0, "straight": 0},
 "formant": {"praat": 30, "snack": 0},
 "f0_any": true, "formant_any": true}
```
判定口径：文件存在且 **>0 字节**（0 字节是中断残留，不算可用，与 1.2 坏缓存自愈口径一致）。

### 2d. 参数

`params_schema.py` 新增（**均 `internal=True`**，不出现在第二步参数列表，但仍进 defaults/params.csv）：
- `f0BaseEngine`：choice，default `praat`，可选 `praat/snack/straight`
- `formantBaseEngine`：choice，default `praat`，可选 `praat/snack`（STRAIGHT 不产共振峰）

`params_validate.py` 校验取值，非法值报错并回默认。

## 3. 界面规格（第三步）

在 `data-panel="3"` 内、「运行前检查」卡**之前**插入：

```
<div class="card" id="baseEngineCard">
  <h2>其他参数的基准引擎</h2>
  <p id="baseEngineHint">…</p>
  <div class="block" id="f0BaseRow"><label>基频（F0）基准</label><div class="chip-row" id="f0BaseOpts"></div><p id="f0BaseNote"></p></div>
  <div class="block" id="fmtBaseRow"><label>共振峰（Formant）基准</label><div class="chip-row" id="fmtBaseOpts"></div><p id="fmtBaseNote"></p></div>
  <div id="baseEngineWarn" class="hidden"></div>
</div>
```

行为：
1. **两组独立**（F0 一组、共振峰一组），可各选不同引擎。
2. 每个引擎渲染成一个 chip，带**数量徽标**（`<span class="chip-n">n</span>`）。
3. 数量 0 → chip `disabled` + `chip-off` 类（置灰不可点）；有数量 → 可点，当前选中项加 `active`。
4. **自动回退**：当前基准若不可用（数量 0），自动回退到第一个可用引擎（默认 praat 优先）。
5. **兜底**：`f0_any=false` 或 `formant_any=false` → 显示黄色警示条（`warn-hint`，文案「缺少…的基础数据…请先在第 2 步勾选…并运行一次，或先做全量审查」），并**禁用「开始批量处理」**（`btnRun` / `btnRunTop`）。
6. 触发时机：`setStep(3)` 时刷新；`inputDir` 变化（`scanInput`）时刷新。

## 4. 后端校验（`server.validate`）

当勾选了**依赖 F0/共振峰的下游参数**（谐波/斜率/CPP/HNR/SoE/SHR/强度）且：
- 本批**没勾** F0（`pitch`）/ 共振峰（`formant1..5`），且
- `measure/` 里**没有任何**引擎的 F0 / 共振峰对象

→ **error** 拦住批量（字段 `f0BaseEngine` / `formantBaseEngine`）。

若基准指向的引擎对象不存在（但本批会算）→ **warning**，不拦。
