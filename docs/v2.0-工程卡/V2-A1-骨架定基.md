## 2. 操作步骤（逐步执行，每步有检查）

1. **复制目录**（Bash，在仓库根执行）：
   > ⚠️ **路径实测修正（2026-10-26 执行 A1 时发现）**：`scripts/` 与 `samples/` 都**不在 `ps-shell/` 下，而在仓库根**。
   > 原因：`settings.app_base()` = `backend/` 往上三级 = 仓库根，`DEFAULT_SCRIPT_DIR = <APP_BASE>/scripts`。
   > v2 复制后 `APP_BASE` 变成 `ps-shell-v2/`，**必须把根 `scripts/` 与根 `samples/` 复制进 v2**，否则 v2 找不到脚本/样本。
   > `ps-shell/samples/` 是空壳（0 项）；`ps-shell/tests/`、`ps-shell/tools/` 存在但原卡未列，**必须一并复制**（tests 是回归基线）。
   ```bash
   mkdir -p ps-shell-v2
   cp -r ps-shell/backend ps-shell/ui ps-shell/vowel_data ps-shell/tests ps-shell/tools ps-shell-v2/
   cp -r scripts samples ps-shell-v2/          # ← 根目录，非 ps-shell/ 下
   cp ps-shell/app.py ps-shell/serve_only.py ps-shell/README.md "ps-shell/启动 PraatSauce 助手.bat" ps-shell-v2/
   ```
   然后清理复制物中的缓存与历史产物：
   ```bash
   find ps-shell-v2 -type d -name __pycache__ -exec rm -rf {} + 
   find ps-shell-v2 -type d -name measure -exec rm -rf {} +
   find ps-shell-v2 -type d -name output -exec rm -rf {} +
   find ps-shell-v2 -type d -name Resample -exec rm -rf {} +
   rm -f ps-shell-v2/settings.json ps-shell-v2/settings_frozen.json
   ```
   > **measure/ 必清**：根 `samples/` 自带 1.2 示例的中间产物 `samples/2/measure/`（30 个 .Pitch/.Formant），
   > 复制后必须删——否则 v2 首次运行会误判「已审核」。
   > **settings 必须删**（若存在）：1.2 的 settings.json 含本机绝对路径（praatExe/scriptDir/上次目录），复制会让 v2 继承脏状态、且可能指向 1.2 的脚本目录造成互相污染。v2 首次启动自建新 settings。
   > **v2 隔离要求**：v2 的运行端口、`_build` 产物目录、settings 文件**必须与 1.2 全部独立**（端口由 app.py/serve_only.py 决定——若硬编码同一端口，本卡须改为参数化，报告说明）；确保 1.2 与 v2 可同时运行互不干扰。
   检查点：`ls ps-shell-v2` 应见 `app.py backend ui scripts samples vowel_data tests tools README.md serve_only.py 启动 PraatSauce 助手.bat`（**不应见 settings*.json**）；`ls ps-shell-v2/scripts/*.praat | wc -l` = 25；`find ps-shell-v2/samples -name '*.wav' | wc -l` = 30。
2. **建 pysauce 包骨架**：创建 `ps-shell-v2/backend/pysauce/__init__.py`，内容：

   约定：纯算法无 I/O 副作用；NaN 表示未定义；见 docs/v2.0-工程卡/00-总纲.md 第 5 节翻译规则。
