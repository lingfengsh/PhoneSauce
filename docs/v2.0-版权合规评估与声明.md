## 一、结论（先答问题）

| 问题 | 答案 |
|---|---|
| 有没有风险？ | **有一个明确的风险点**：VoiceSauce 的 .m 文件全部声明 `Copyright UCLA SPAPL`，但**分发包里没有任何 LICENSE/许可条款** → 法律上属"保留所有权利"，仅学术惯例免费使用。若我们的 Python 实现被认定为对 MATLAB 源码的"翻译/衍生作品"，严格而言是未经授权的衍生再分发。 |
| 风险有多大？ | **低-中，且可降至极低**。见 §四。降低依据：①算法思想全部有公开论文（思想/方法不受版权保护）；②官方生态存在合法开源的 Python 移植 `voicesauce/opensauce-python`（**Apache-2.0**，作者含 VoiceSauce 原作者 Kristine M. Yu）——我们可合法以其为表达基底；③上游 PraatSauce（同为 VS 算法移植）以 MIT 存续多年；④非商业学术工具。 |
| 怎么消除？ | **"表达分层"策略**（§五）：OS-P 覆盖的模块以 OS-P（Apache-2.0）为表达基底并保留 attribution；其余模块按公开论文独立实现，MATLAB 蓝本只做**行为语义仲裁**（参数、系数、分支行为=事实，不受版权保护）；**refs/ 的 MATLAB 源码永不进仓库、永不进安装包**。 |

## 三、法律框架（简明版）

1. **思想 vs 表达**：算法、公式系数、参数默认值、输出列名、行为口径是"方法/事实"，**不受版权保护**（中美一致： idea/expression 二分；中国著作权法保护表达不保护思想）。对齐 VoiceSauce 的数值行为 = 合法。
2. **表达受保护**：具体代码结构、语句组织、注释是表达。**翻译成另一语言通常构成衍生作品**（中国著作权法 §10 翻译权；美国 17 USC §106(2)）。未经许可翻译 + 再分发 = 侵权暴露——这是唯一真实风险点。
3. **我们的姿态**：工程卡已要求"注释只写要点、命名重排、表达重写"，且测试锚点由我们独立复算——表达独立度较高。但为把"结构沿袭"降到最低，采取 §五分层。
4. **bug-for-bug 行为兼容**（如保留 pickpeaks 单峰疏漏）属行为兼容，与版权无关，照做。
5. **二进制外部程序**（praat.exe GPL-3、snack.exe GPL-2+）：与本项目（MIT）属"聚合分发"，各守各的许可即可——1.2 已对 praat.exe 履行，2.0 对 snack.exe 照办。

## 五、定案：表达分层策略（写进 00-总纲 R7）

| 层 | 模块 | 表达基底 | 义务 |
|---|---|---|---|
| A：OS-P 覆盖 | shrp/SHR（shrp.py 21KB 全量 + helpers.py）、F0 的 Praat 包装（praat.py）、谐波幅度（harmonics.py，简版） | **文件级 vendored（2026-10-26 二次拍板）**：OS-P 源文件直接拷入 `pysauce/_vendor/`（osp_ 前缀改名），原样或修改后使用；与 v1.37 有出入处按蓝本仲裁；**Snack 的 OS-P 包装（snack.py）不搬**——它走 Tcl 路径，与我们 snack.exe 直调不同路 | vendored 文件头（§六.3 模板一）；NOTICES 收录；LICENSES/Apache-2.0.txt；**禁止改标 MIT**；改动逐条记 modified |
| B：OS-P 未覆盖 | CPP、HNR（de Krom）、Energy、SoE、2K/5K、H42K/H1A1A2A3 斜率组合、fminsearchbnd 复刻、engine 编排 | **公开论文思想独立实现**；MATLAB 蓝本仅用于行为语义仲裁（参数/系数/分支/列名） | 文件头标"独立实现+论文引用"（§六.3 模板二）；不逐行直译 MATLAB |
| C：外部程序 | praat.exe、snack.exe | 原样分发 | GPL 许可文本 + 源码获取途径 |

> 注意：A 层与 B 层的**行为语义**都以 v1.37 为准、数值锚点不变——分层只改变"表达从哪来"，不改变测试与验收。
